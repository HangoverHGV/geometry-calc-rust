# Changelog: Isosceles Triangle Implementation

## Overview
Added a dedicated module for isosceles triangle geometry calculations, including UI visualization and backend processing logic. This update maintains architectural consistency by separating UI layout definitions in `.slint` and business logic in the Rust backend.

## UI Changes (`triangles.slint`)
* **New Page Components**: Updated the `Triangles` component to include a `TabWidget`, supporting both "Right angle" and "Isosceles" modes.
* **Visual Assets**: Integrated `images/isosceles-triangle.svg` styled to match existing project aesthetics: vibrant blue stroke (`#2563eb`), 6px stroke width, and clean sans-serif labeling.
* **Dynamic Inputs**: Implemented state-synced `LineEdit` components for isosceles parameters: `input-ab-text`, `input-bc-text`, `input-abc-is-angle`, and `input-bac-is-angle`.
* **Interactive UX**: Added a "Clear" button for the isosceles tab with dynamic state-based styling (gray background on press, red default).
* **Real-time Evaluation**: Configured calculation triggering via `edited => { root.do_calculate_is(); }` for immediate geometric feedback.

## Backend Logic
* **Callback Interface**: Added `calculate-isosceles-tringle(string, string, string, string)` to the Rust-Slint bridge.
* **Mathematical Implementation**: Introduced `calculate_all_isosceles_elements` in Rust to handle the trigonometric mapping of sides and angles for an isosceles triangle ($AB=AC$).
* **Validation**: Implemented post-calculation geometric validation to ensure triangle inequality and angle sum integrity ($180^\circ$) are maintained regardless of input type.
* **Stability**: Added robust floating-point clamping and epsilon-based checks to prevent numerical singularities.

## Assets
* **Added**: `images/isosceles-triangle.svg`.
