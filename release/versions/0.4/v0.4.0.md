## [0.4.0] - 2026-08-25

### Added

- **BOM Calculator page.** New "Upload Spreadsheet" button opens a native
  file dialog (via `rfd`) filtered to `.csv`, `.xls`, `.xlsx`, `.xlsm`, and
  populates a scrollable table with the parsed result.
- **Spreadsheet import** (`src/bom_calculator/bom_calculator.rs`). Reads
  Fusion 360 BOM exports via `calamine` (Excel formats) or the `csv` crate,
  keyed to the standard export column layout (`Item`, `Part Number`,
  `Thumbnail`, `BOM Structure`, `Unit QTY`, `QTY`, `Base QTY`, `Volume`,
  `Mass`).
- **Custom-part filtering.** Rows where `Unit QTY` is `"Each"` — parts
  drawn/modeled directly rather than cut from stock — are excluded, leaving
  only length-based metal profiles.
- **Cut-position merging.** Multiple rows for the same profile at different
  cut lengths (e.g. `CSN 425720 - 80x6-12000`, `...-2000`, `...-1700`, ...)
  are grouped into a single summary row by stripping the trailing
  `-<length>` suffix from `Part Number` via regex. Tolerates the extra
  whitespace Fusion sometimes inserts before the dash
  (`"...80 x 80 x 3  - 1300"`).
- **Per-part stock estimate.** Each summary row reports total length (m),
  total mass (kg), and independent bar counts for both 6m and 12m stock —
  `ceil(total_length / bar_length)` for each size — plus the resulting
  purchased length (`bars × bar_length`) for each.
- `BomRow` table with columns: Part Name, Length (m), Mass (kg), 6m Bars,
  6m Total, 12m Bars, 12m Total.

### Fixed

- **Duplicate `BomRow` struct** declared independently in `app.slint` and
  `bom_caluclator.slint` caused a `[BomRow] != [BomRow]` type mismatch at
  build time — Slint identifies structs by declaration site, so two
  identically-shaped structs in different files are still distinct types.
  Consolidated to a single declaration, imported everywhere it's used.
- **Mass totals silently dropped rows** where Fusion couldn't compute
  volume/mass and exported `*Varies*` in that cell. These rows are now
  explicitly excluded from the mass sum and flagged in the UI rather than
  parsed as zero without comment.

### Known limitations

- 6m/12m bar counts are independent "if you only bought this size" figures
  based on total merged length; they don't check whether any individual cut
  piece actually fits within that stock length. A part containing a 12m cut
  will still get a 6m bar count, which isn't physically obtainable from 6m
  stock.
- No cutting layout or nesting is produced — the counts are a quick ordering
  estimate, not a cut plan.
