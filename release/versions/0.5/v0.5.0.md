## [0.5.0] - 2026-09-04

### Added

- **Scheduled shutdown** — the time picker in the shared page header now arms a Windows shutdown for the selected duration. The picked time is read as a countdown (`hour`/`minute`/`second` from the point of confirmation), not a wall-clock target.
- **Live countdown** — a `hh:mm:ss` readout appears in the page header while a shutdown is pending, driven by a 1-second timer in `AppWindow`.
- **Cancel Shutdown button** — appears alongside the countdown whenever a shutdown is armed; issues `shutdown /a` and clears the stored deadline.
- **Countdown persistence** — the shutdown deadline is written to `%LOCALAPPDATA%\cad-helper-3d\shutdown.txt` as a Unix timestamp and restored on startup, so the countdown survives closing and reopening the app. Stale deadlines (already elapsed) are discarded on read.
- **`schedule_shutdown` module** — new `mod.rs` / `schedule_shutdown.rs` / `ui.rs` structure, mirroring the `bom_calculator` and `batch_printing` module pattern. Command execution and state persistence stay in `schedule_shutdown.rs`; all Slint bindings live in `ui.rs`.
- **`Backend` global** (`globals.slint`) — carries `schedule-shutdown`, `cancel-shutdown`, and the `shutdown-remaining` / `shutdown-pending` / `remaining-text` properties. Declared once and imported, avoiding the per-page callback forwarding that `sync-db` requires.

### Changed

- `Page` (`components/page.slint`) now imports `Backend` and wires the `TimePickerPopup` `accepted` handler to `Backend.schedule-shutdown` instead of only calling `debug(time)`.
- `app-window.slint` re-exports `Backend` so the global is reachable from Rust via `ui.global::<Backend>()`.

### Notes

- Shutdown commands run with `CREATE_NO_WINDOW` on Windows to suppress the console flash.
- `schedule` issues `shutdown /a` before arming a new countdown; Windows rejects a second `/s` while one is already pending.
- `cancel` treats exit code 1116 (*no shutdown was in progress*) as success rather than an error, so pressing Cancel against a stale countdown clears state quietly.

### Known limitations

- The countdown decrements once per second in the UI rather than recomputing from the stored deadline, so it can drift by a few seconds over multi-hour durations. Windows owns the authoritative timer.
- If a shutdown is cancelled externally (e.g. `shutdown /a` in a terminal) while the app is closed, the restored countdown will be inaccurate until Cancel is pressed. Reconciling against Event ID 1074 in the System log was considered and deferred — the log text is localized and unpleasant to parse.
- Windows-only. `shutdown` on Linux takes minutes or `HH:MM` and requires root; `run_shutdown` is the intended place for a `#[cfg(target_os = ...)]` split.
