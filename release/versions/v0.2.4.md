# Changelog - v0.2.4
This release introduces native batch printing capabilities for PDF files on Windows, robust UI error/success feedback, and seamless deployment bundling for the required dependencies.

## 🚀 New Features & Enhancements
1. Native PDF Batch Printing (winprint & PdfiumPrinter)
   Replaced direct raw-byte printing with the high-performance winprint crate powered by PDFium.

Added native rendering support for PDFs so print jobs correctly hit the Windows Print Spooler and show up in the system queue.

2. Native File Dialog Picker (rfd)
   Implemented multi-file selection for PDF documents using the rfd crate.

Added proper file extension filters (.pdf) to ensure users can easily locate and select files to print.

3. Integrated UI Feedback (MessageBox)
   Connected print outcomes directly to the application's custom MessageBox component.

Users now receive clear visual popups indicating either a successful queueing operation (with file counts and printer names) or a descriptive error notification if printing fails.

## 🛠️ Improvements & Refactoring
Unified Printer Device Management: Switched printer enumeration entirely over to winprint (PrinterDevice::all()) to guarantee strict naming consistency between the Slint UI model and the underlying Windows print drivers.

Streamlined UI State Tracking: Added an active printer tracker in the UI layer to effortlessly pass the selected printer name straight into the background file dialog and printing pipeline.

## 📦 Build & Deployment Updates
Automated DLL Packaging: Updated Makefile.toml for Windows to automatically stage pdfium.dll alongside the compiled executable (cad-helper-3d.exe).

Inno Setup Integration: Updated build_assets/installer.iss to package pdfium.dll directly into the final standalone setup wizard (cad-helper-3d-setup.exe), ensuring out-of-the-box printing functionality for end users.
